# 운영 콘솔 UI 개선

기준일: 2026-10-14. 기존 API·DB와 계층 모델을 유지하고 탐색·조회 화면을 개선했습니다. 새 UI 라이브러리나 유료 서비스를 추가하지 않았습니다.

## 확인한 참고 화면과 문서

- [Headlamp Projects](https://headlamp.dev/docs/latest/learn/projects/): 공식 문서의 Project Resources·Overview 화면에서 좌측 탐색, 자원 종류 구분, 상태·Namespace 등 열 중심 목록과 개요·관계 탭을 확인했습니다.
- [Rancher 클러스터 접근](https://ranchermanager.docs.rancher.com/how-to-guides/new-user-guides/manage-clusters/access-clusters/): 클러스터 탐색과 특정 클러스터의 대시보드·리소스 범위를 구분하는 흐름을 참고했습니다.
- [Lens Renderer Extension v5.2.6 문서](https://api-docs.k8slens.dev/v5.2.6/extensions/guides/renderer-extension/): 좌측 클러스터 메뉴·리소스 상세 확장 구조를 참고했습니다. 최신 버전 화면이 동일하다고 주장하지 않습니다.

제품 브랜드·코드·아이콘·화면 이미지를 앱에 복사하지 않았습니다. 공식 화면 이미지는 검토용 로컬 파일로만 사용하며 실행 UI에는 자체 SVG 아이콘과 실제 API 데이터를 사용합니다. 해당 OSS를 설치하거나 연동한 작업도 아닙니다.

## 적용 범위와 이유

| 개선 | 적용 방식 | 목적 |
|---|---|---|
| 콘솔 공통 레이아웃 | 상단 문맥·자동 갱신, 좌측 탐색기, 중앙 목록, 우측 상세 | 조작 위치를 고정하고 목록 탐색 중 상세를 확인 |
| 유형별 바로가기 | Cluster·Node·Namespace·Pod 메뉴와 건수 카드 | 유형 이동 시 검색·부모·상태·커서를 초기화해 전역 조회 |
| 조회 범위 표시 | 선택 부모 이름·검색 범위 설명·초기화 버튼 | 부모 목록과 전역 검색의 차이를 명확하게 표시 |
| 열 중심 목록 | 이름·경로, 유형, 상태, 부모, 갱신 시각 | 이름만으로 비교하기 어려운 문맥을 함께 확인 |
| 상태 요약 | 보관 중인 창의 정상·주의·오류 수 | 조회창 상태를 빠르게 파악; 전체 DB 통계와 구분 |
| 상세 패널 | 닫기·개요/관계 탭·조상 이동·Node meter | 같은 화면에서 속성·위치 확인 |
| 키보드 | `/` 검색 포커스, `Escape` 상세 닫기, 상세 탭 좌우 이동 | 반복 탐색을 빠르게 수행하고 포커스 유지 |
| 모바일 | 유형 메뉴 유지, 계층은 기본 접힘·버튼으로 펼침, 상세 세로 배치 | 작은 화면에서 목록 우선 노출, 가로 넘침 방지 |

`계층에서 위치 보기`는 모바일에서도 계층을 펼치고 해당 경로로 이동합니다. 유형 메뉴나 건수 카드로 다른 유형을 선택하면 이전 상세를 닫고 새 조회로 이동합니다. 조건 초기화는 검색·상태·부모를 해제합니다.

## 데이터와 표시의 경계

- 상단 네 건수는 `/summary`의 실제 테이블별 수입니다.
- 상태 요약은 **현재 보관한 조회창 최대 500개**의 집계입니다. 화면에 `전체 DB 집계 아님`을 표시하고 새 DB 집계 API를 만들지 않았습니다.
- Node CPU·메모리 meter는 상세 API의 현재값입니다. 추이 차트·실측 Kubernetes 메트릭을 생성하지 않습니다.
- 목록 갱신 시각은 `updatedAt`입니다. 상세에는 전체 날짜·시간을 표시합니다. 좁은 목록에서는 일부 열을 숨기고 상세에서 확인합니다.
- UI에 `MOCK DATA`, 읽기 전용 안내를 표시합니다. 이 과제의 Cluster → Node → Namespace → Pod는 탐색 모델이며 실제 Kubernetes 관계와 같다는 뜻이 아닙니다.
- 로그·터미널·YAML 편집·배포·GPU·알림 등 미구현 메뉴를 추가하지 않았습니다. 활성처럼 보이는 가짜 기능을 두지 않습니다.

## 유지한 성능 전략

행 높이 60px·트리 44px, 최대 500개 목록 캐시·24개 계층 페이지 캐시, 제한된 GET·폴링·취소·백오프를 유지했습니다. SVG는 표시되는 행에만 렌더링합니다. 목록 컬럼을 늘렸다고 전체 10만 건을 로딩하거나 DOM에 표시하지 않습니다. CPU 4x·캐시 OFF의 실제 측정은 [성능 검증 보고서](PERFORMANCE_RESULTS.md)에 기록했습니다. 초기 레이아웃·날짜 표시의 불필요한 계산과 무한 요청 대기를 보강했습니다.

## 검증과 실제 캡처

- 타입 검사·프로덕션 빌드 통과.
- Vitest 56개 통과: 기존 44개에 콘솔 UI 6개, 시간 초과·취소·타이머 정리 3개, 초기 높이 측정·스크롤 초기화·날짜 포매터 재사용 3개 추가.
- 실제 PostgreSQL API Chromium E2E 7개 통과: 기존 5개에 콘솔 조작·키보드와 390px 모바일 레이아웃 검증 추가.
- 기존 검색·상태 필터·경로 이동·500행 캐시·자동 반영·1,200px 스크롤 유지 테스트도 재통과했습니다.
- 모바일은 가로 넘침 없음, 계층 펼침·접힘, 상세 열기·닫기를 검증했습니다. 실제 휴대전화 기기 테스트를 수행한 것은 아닙니다.
