# 2단계 조회 API 구현·검증 보고서

당시 Maven/POM 명령은 역사 기록입니다. 현재 실행·보고서 경로는 [Gradle 빌드](GRADLE_BUILD.md)를 따릅니다.

이 문서는 2026-10-13 당시 결과입니다. 이후 실제 DB·정식 빌드·브라우저 검증을 완료했으며 현재 결과는 [후속 보고서](STAGE4_REPORT.md)에 기록했습니다.

이 보고서는 초기 JDBC 조회 구현 당시의 기록입니다. 현재는 [JPA Entity·DTO 조회](JPA_QUERY_DESIGN.md)로 전환했으며 최신 검증은 [기준 문서](PROJECT_GUIDE.md)를 참고합니다.

## 구현 범위

유형별 목록·부모별 하위 목록, 유형별 상세, 최대 4단계 경로, 이름 부분 검색, 상태·유형 필터를 구현했습니다. 자세한 계약은 [API 문서](API.md), 전체 상태는 [프로젝트 기준 문서](PROJECT_GUIDE.md)를 참고합니다.

## 조회 전략

- 요청마다 전체 리소스를 메모리로 읽지 않습니다.
- 목록은 부모·상태·이름·ID 커서 조건을 SQL에 적용하고 limit + 1개만 반환합니다.
- 전체 검색은 각 유형별 후보를 limit + 1개로 제한한 뒤 depth·ID로 병합합니다. 외부 병합 대상은 최대 404개이며 API 반환은 최대 100개입니다. 이 제한은 DB가 실제로 읽는 행 수까지 404개라는 뜻이 아닙니다.
- 상위 경로는 고정 깊이 JOIN으로 반환합니다. 요청 결과마다 부모를 별도 조회하는 애플리케이션 N+1 패턴을 피합니다.
- hasChildren은 인덱스로 조회 가능한 EXISTS 조건이며 하위 전체 데이터를 응답에 담지 않습니다.
- SQL 테이블·컬럼 이름은 서버 enum에서만 선택합니다. 사용자 검색값은 파라미터 바인딩과 LIKE 문자 이스케이프를 적용합니다.
- JPA Entity 그래프 대신 명시적 읽기 SQL과 DTO를 사용합니다. 현재 서비스의 쿼리·반환 범위를 명확히 제어하기 위한 선택이며 ORM 검증 성과로 표현하지 않습니다.

## 인덱스

V2는 parent + ID, status + ID, 이름 검색용 pg_trgm GIN 인덱스를 추가합니다. V1의 parent + status + ID는 상태가 없는 ID 정렬을 모두 해결하지 않으므로 parent + ID를 별도 구성합니다.

pg_trgm은 부분 검색을 지원하지만 짧거나 흔한 검색어에서 효과가 제한될 수 있습니다. 인덱스 사용·응답 시간 개선은 EXPLAIN (ANALYZE, BUFFERS)와 실제 DB 측정 후 판단합니다. V2는 확장 생성 권한이 필요하며 기본 과제 PostgreSQL 이미지의 초기 관리 계정으로 실행합니다.

## 실행한 검증

- Java 21 javac로 모든 main 소스와 단위 테스트 컴파일: 통과.
- ResourceQueryTest 14개: 요청값·조건 범위·와일드카드 처리·커서 형식 검증.
- ResourceServiceTest 10개: 페이지 크기·다음 커서·부모 존재·하위 유형·상세·경로·leaf 처리.
- ResourceControllerTest 10개: 실제 Spring MVC 라우팅·JSON 직렬화·400·404·오류 내용 경계. 저장소는 stub이며 실제 DB를 사용하지 않습니다.
- ResourceRepositorySqlTest 6개: 쿼리 구성·브랜치 상한·이름값 바인딩·커서 조건·NamedParameter 바인딩.
- 합계 **40개 실행, 40개 통과, 실패·건너뜀 없음**.

검증은 설치된 캐시 라이브러리(Spring Boot 3.5.10, Spring 6.2.15, Jackson 2.19.4, JUnit 5.10.5)를 사용한 보조 검증입니다. POM의 Spring Boot 3.5.16 및 관리 의존성으로 정식 Maven 빌드·테스트를 실행한 결과는 아닙니다. 프로젝트 버전을 캐시 버전으로 낮추지 않았습니다.

## 작성했으나 실행하지 못한 검증

Testcontainers PostgreSQL 17 기반 ResourceApiIntegrationTest 12개를 작성했습니다. V1·V2 적용 후 10만 Pod에서 부모별 목록, 제한된 응답, 다음 ID, 필터·리터럴 검색, 검색 경로·유형 간 페이지 이동, 유형별 속성, 400·404·커서 오류를 검증합니다.

Docker·네트워크 제한 때문에 실제 DB 검색 결과, 확장·인덱스 생성, 실행 계획 및 API 성능은 검증되지 않았습니다. 보조 단위 테스트 통과를 실제 DB·서버·브라우저 통과로 표현하지 않습니다.
