# 프로젝트 기준 문서

이 문서는 Infrastructure Monitoring Service의 현재 기능, 구조, 처리 흐름과 검증 상태를 관리합니다. 기능과 실행 방식이 바뀔 때 README 및 관련 설계 문서도 함께 갱신합니다.

## 목적과 범위

Mock 인프라 데이터를 실제 DB에 저장하고 대용량 리소스 탐색 성능을 검증하는 독립 과제입니다. 목표 규모는 Cluster 20개, Node 200개, Namespace 2,000개, Pod 100,000개입니다. 실제 Kubernetes 연동은 하지 않습니다.

## 현재 구조와 처리 흐름

```text
scripts/seed.sql → PostgreSQL의 4개 계층 테이블
Vue 초기 화면 → Vite /api 프록시 → Spring Boot → SQL 건수 조회 → 화면 표시
탐색·검색 요청 → 요청값·커서 검증 → 제한된 SQL 조회 → DTO·경로·다음 커서 반환
Spring Boot 기동 → Flyway 마이그레이션 → 테이블 및 인덱스 생성
JUnit 통합 테스트 → Testcontainers PostgreSQL → Flyway 스키마 확인
```

현재 작성된 기능은 건수·목록·하위 목록·상세·경로·검색·상태 필터 API, 초기 요약 화면, V1·V2 스키마 및 인덱스, SQL 데이터 생성과 테스트입니다. 계층 탐색·상세·검색·필터 화면, 가상 스크롤 및 상태 갱신은 미구현입니다. 데이터 생성 파일과 API 코드가 있다는 사실은 실제 10만 건 적재·조회 검증과 구분합니다.

| 기능 | 서버 구현 | 화면·실제 DB 검증 |
|---|---|---|
| 리소스 규모 | 건수 API 및 초기 화면 코드 | DB 연동 미검증 |
| 목록·하위 탐색 | 부모별 조회, ID 커서, 최대 100개 | 화면 예정, 실제 DB 미검증 |
| 상세·경로 | 유형별 속성과 최대 4단계 경로 | 화면 예정, 실제 DB 미검증 |
| 검색·필터 | 이름 부분 검색과 상태·유형 조건, 결과 경로 | 화면 예정, 실제 DB 미검증 |
| 응답·입력 정책 | 요청값·커서 검증, 400·404·503 | 캐시 환경 단위/MVC 검증 통과 |

## 기술과 실행 경계

Java 21 / Spring Boot 3.5 / PostgreSQL 17 / Flyway / Vue 3 / TypeScript / Vite / Testcontainers를 구성했습니다. TanStack Virtual 의존성을 추가했으나 화면에 아직 적용하지 않았습니다. JPA 의존성은 초기 구성에 남아 있지만 현재 조회는 JdbcTemplate/NamedParameterJdbcTemplate과 DTO로 처리합니다. JPA Entity 그래프를 로딩하거나 ORM 성능 검증을 완료한 프로젝트라고 설명하지 않습니다.

V2는 PostgreSQL의 pg_trgm 및 이름 GIN 인덱스, 부모·ID와 상태·ID 인덱스를 추가합니다. 부분 문자열 검색과 커서 조회를 지원하기 위한 설계이며 실제 실행 계획·성능 수치는 미측정입니다. 각 SQL에는 3초 제한을 적용하며 이 제한은 전체 요청 지연 목표를 보장하는 수치가 아닙니다.

기존 프로젝트와 충돌을 줄이기 위해 화면 5174, API 8081, DB 5544를 사용하며 루프백에 바인딩합니다. 개발 DB의 공개된 기본 자격 정보는 실사용 계정 정보가 아닙니다. 인터넷 운영 배포 및 사용자 인증은 초기 범위 밖입니다.
