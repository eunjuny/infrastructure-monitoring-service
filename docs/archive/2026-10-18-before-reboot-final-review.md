# 인증 환경 성능 측정 결과

## 최신 재검증

WH-050의 [초기 작업 분리·실제 Chrome 재검증](../PERFORMANCE_RECHECK.md)을 현재 근거로 사용합니다. 진단 표시 수정 후 프론트108개·실제 Keycloak14개를 통과했습니다. 개별 성공 캡처와 단발 초과가 있는 반복 실행을 구분하며, 첫 화면 반복 안정성·native FPS 전 구간 최솟값 판정은 미완료입니다. 아래 headless 통계는 해당 이전 실행의 범위로 보존합니다.

## WH-049 실제 DevTools 후속 확인

아래 표는 기존 `per-goal-evidence-20261018` headless 반복 실행 결과입니다. 이후 Chrome 155 실제 GUI의 CPU4×·캐시 OFF Performance 기록에서는 첫 화면 658.10ms(1440×1000 추가 확인 619.13ms), 최초 펼침 278.72ms가 기록됐습니다. 최초 펼침은 접근성 조회가 겹쳐 계측 간섭 분리가 필요합니다. 다른 선택 기록은 재펼침48.40·접기37.98·검색142.32·필터138.65·수동57.96·변경 수동122.10·변경 자동75.90ms입니다.

실제 목표별 원본은 [Chrome Performance 캡처](../CHROME_PERFORMANCE_CAPTURE.md), [수치 목록](../performance/2026-10-18-native-devtools.json)에 보관합니다. FPS 미터91.2fps는 순간 관측이고 전체 구간55fps 유지는 미검증입니다. 작업관리자90.8MB는 별도 시점입니다. **이전 headless 결과만으로 현재 모든 가이드 목표를 충족했다고 판정하지 않습니다.**

## 측정 방법

첫 화면은 유효한 Keycloak SSO 세션으로 페이지 navigation을 시작한 시점부터 Cluster 목록이 표시되어 조작 가능한 시점까지입니다. OIDC 왕복을 포함하며, 인증 복귀 후 앱 자체 준비 시간도 별도로 기록했습니다. 사용자의 비밀번호 입력 시간은 포함하지 않습니다.

펼침·접기·필터·수동 갱신은 클릭 직전부터 결과가 반영될 때까지 측정합니다. 검색은 디바운스 종료 이후, 자동 갱신은 폴링 요청 시작 이후를 기준으로 합니다. 테스트 전용 `performance.mark()`/`performance.measure()`와 DOM 결과 확인을 같이 수행하고, 결과가 맞은 뒤 두 번의 animation frame을 기다립니다. 첫 화면의 SSO 왕복은 문서 이동을 포함한 브라우저 자동화 시간이며, callback User Timing은 앱 문서가 열린 뒤 목록 표시까지의 보조 계측입니다. 폴링 주기 5초의 탐지 대기는 처리 시간과 구분합니다.

자동/수동 변경 반영 검증은 테스트 Pod의 상태·시각을 잠시 변경해 목록·선택 상세의 반영과 빈 목록 깜빡임 여부를 확인합니다. 검증 후 원래 상태·시각으로 복원했습니다.

## 적용한 성능 전략

- 첫 Cluster 목록을 우선 표시하고 사용자 표시·건수·계층 루트를 후속 조회합니다.
- 상세·이력·운영 화면 코드를 필요 시 로드하고 날짜·건수 포맷의 초기 실행 비용을 줄였습니다.
- 갱신은 현재 조회 창·펼친 계층·선택 상세에 한정하고, 상태 변화로 바뀌지 않는 전체 리소스 건수는 다시 집계하지 않습니다.
- 목록 500개·계층 캐시 상한과 가상 렌더링을 유지합니다.
- 인증은 PKCE·JWT·서버 Cluster 권한 검증을 적용합니다.

회귀 검증은 서버 140개, 프론트 96개, 실제 Keycloak 브라우저 14개를 통과했습니다. 성능 측정은 단일 로컬 사용자의 화면 응답을 검증하며 동시 사용자 부하·서버 이중화의 처리 용량 시험과는 구분합니다.
