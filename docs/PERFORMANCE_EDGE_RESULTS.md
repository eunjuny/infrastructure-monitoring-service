# 추가 검색·다중 계층·자동 갱신 검증

기준일: 2026-10-14. 원격 접속 상태에서 Infrastructure Monitoring Service의 실제 PostgreSQL·API·프로덕션 화면을 검증했습니다. 제품의 API·DB 스키마·UI·폴링 정책은 변경하지 않았습니다. 추가 검증 스크립트와 실행 명령·문서만 보강했습니다. 이 후속 작업은 커밋·푸시하지 않았습니다.

## 두 작업의 현재 상태

| 요청 | 상태 | 근거 |
|---|---|---|
| Chrome 작업관리자의 실제 탭 메모리 | 미확인 | 네이티브 접근이 Mac 잠금으로 거부됐고 마지막에 다시 확인해도 잠금 상태였습니다. 잠금을 우회하거나 비밀번호를 요청하지 않았습니다. |
| 추가 검색·다중 계층·자동 갱신 성능 | 완료 | 검색 100회·부모 펼침 160회·자동 갱신 20회, 측정 오류·목표 초과 0회 |

원격 접속 자체는 headless 브라우저와 로컬 서버 검증을 막지 않습니다. 다만 Chrome 작업관리자는 네이티브 창 접근이 필요합니다. 따라서 아래 JS heap이나 이전 보고서의 renderer RSS를 사용해 탭 메모리 300MB 기준이 통과했다고 판단하지 않습니다. 실제 확인을 이어가려면 Mac 잠금 해제가 필요합니다.

## 환경과 재현

- Apple M1 Pro·RAM 16GiB, Chromium 156.0.8078.4, Playwright 1.64.0.
- CPU 4x, HTTP 캐시 OFF, 별도 네트워크 제한 없음, 1440 × 1000, headless.
- 프로덕션 빌드 preview 5174 → API 8081 → 실제 PostgreSQL 17.11.
- Cluster 20·Node 200·Namespace 2,000·Pod 100,000, 동작 중인 mock 프로필.
- 하나의 context에서 실제 UI 조건을 초기화하며 반복했습니다. 브라우저 최초 진입 측정이나 여러 사용자의 동시 부하 시험은 아닙니다.
- 검색은 250ms 디바운스 이후 요청 시작부터 실제 결과 DOM·빈 결과 표시 및 두 번의 RAF까지입니다. 계층은 클릭부터 실제 하위 행 표시, 자동 갱신은 첫 요청부터 변경 배지·조회 그룹 완료 표시까지입니다.
- 테스트 코드가 응답을 복제해 조건을 검증하는 비용도 포함합니다. 이 코드는 제품 번들에 포함하지 않습니다.

```bash
cd frontend
PERF_LABEL=edge-check npm run test:performance:edges
```

과제 DB의 Pod 1을 직접 변경하는 검증이므로 실사용 DB에 실행하지 않습니다. 마지막 테스트 변경 시각이 그대로 유지된 경우에만 최초 상태·updated_at을 복원합니다. 이번 최종 실행은 조건부 복원에 성공했습니다. 다른 속성·행·테이블은 이 검증을 위해 수정하지 않았습니다.

[측정값 배열·요청 경로 집계 JSON](performance/2026-10-14-edge-results.json), [전체 프로토콜](PERFORMANCE.md)을 참고합니다. 개별 요청의 시작·응답 헤더 시각을 포함한 전체 원본은 Git 제외 경로 `frontend/.validation/performance/edge-final.json`에 보관합니다.

단위: ms. 표시는 소수점 한 자리로 반올림했고 원본 JSON에는 각 측정값과 요청 목록을 보관했습니다.

| 시나리오 | 횟수 | 중앙값 | p95 | 최대 | 목표 | 초과 |

| 한 글자 미일치 검색 `z`, Pod | 20 | 99.1 | 101.2 | 102.4 | 300 | 0 |
| 흔한 부분 문자열 `pod`, Pod | 20 | 48.0 | 51.4 | 53.7 | 300 | 0 |

검색 결과의 이름·선택 유형·상태 조건과 실제 표시된 첫 항목을 확인했습니다. 한 글자 미일치는 실제 빈 결과가 보일 때 종료했습니다. 단문 검색을 막거나 검색 방식을 바꿔 목표를 통과시킨 것이 아닙니다. 이번 10만 건 환경에서는 추가 인덱스·캐시 도입을 요구할 병목이 관측되지 않았지만 더 큰 데이터와 다른 검색어에서 동일한 수치를 보장하지 않습니다.

## 여러 계층 펼침

각 반복에서 트리를 초기화한 후 Cluster 1~8을 순서대로 펼쳤습니다. 여덟 번의 합계가 100ms 이내라는 뜻은 아니며 각 클릭의 처리 시간을 160회 기록했습니다. 아홉 번째 부모를 펼친 후 첫 번째 펼침 상태가 해제되는 제한 정책도 확인했습니다. 여러 부모가 동시에 펼쳐 있어도 모든 하위 데이터를 미리 받지 않습니다.

## 자동 갱신의 두 시간

목록 5페이지·500개, 펼친 부모 8개와 루트, 선택 상세를 유지한 상태에서 DB의 Pod 1 상태·시각을 바꿨습니다. 변경 확인 후 자동 갱신을 활성화해 다음 요청을 기다리는 시나리오입니다.

| 시간 | 중앙값 | 최대 | 의미 |
|---|---:|---:|---|
| 변경 확인 → 첫 폴링 요청 | 5,024.6ms | 5,030.9ms | 기본 5초 타이머와 UI 조작 비용을 포함한 대기 |
| 첫 요청 → 변경 배지·그룹 완료 표시 | 94.4ms | 111.6ms | 실제 조회·본문 처리·화면 반영 시간 |

따라서 데이터 변경을 112ms 안에 발견한다는 의미가 아닙니다. 이 시나리오에서는 약 5초를 기다린 후 약 100ms 안에 화면에 반영됐습니다. 숨긴 탭·오프라인·사용자 입력·진행 중 요청 때문에 폴링이 지연되는 경우까지 위 대기 시간으로 보장하지 않습니다.

각 자동 갱신에서 실제 15개 GET을 관측했습니다. 이 시나리오는 `계층에서 위치 보기`로 페이지 밖 목표를 고정하지 않은 조건입니다. 고정된 목표를 추가 상세 조회하는 다른 탐색 상태까지 항상 15개라는 뜻은 아닙니다.

- 현재 목록 5개 페이지: 커서를 다시 평가하므로 순차 조회합니다.
- 계층 9개 페이지: 루트와 펼친 부모 8개입니다.
- 선택 상세 1개: 기존 선택을 유지합니다.
- 전체 건수 `/summary`: 자동 갱신에 포함되지 않았습니다.

## DOM·JS heap 보조 확인

강제 GC 없이 세 시점에서 관측했습니다. 자연적인 GC로 JS heap은 증가·감소할 수 있습니다.

| 시점 | 목록 렌더 행 | 트리 렌더 행 | 문서 요소 | JS heap, MiB |
|---|---:|---:|---:|---:|
| 검색 100회 후 | 14 | 17 | 456 | 6.01 |
| 부모 8개·500행·상세 준비 | 14 | 17 | 559 | 16.86 |
| 자동 갱신 20회 후 | 14 | 17 | 559 | 5.57 |

목록 캐시는 500개를 유지하고 DOM 요소 수는 갱신 후에도 559개였습니다. 이 관측에서 반복 갱신으로 DOM이 계속 누적되는 현상은 확인하지 않았습니다. 장기 누수 부재나 전체 탭 메모리 사용량을 증명한 것은 아닙니다. Chrome 작업관리자의 `Memory footprint`는 여전히 별도 확인 대상입니다.

## 검증 도구의 예비 수정

첫 3회 예비 실행에서는 검색·계층 측정 후 psql의 `UPDATE 1` 명령 태그가 JSON 출력에 붙어 측정 도구의 파싱이 실패했습니다. 제품 API나 화면 실패가 아닙니다. psql quiet 출력을 사용해 수정했고 수정 후 3회 예비 검증과 최종 20회 반복을 오류 없이 완료했습니다. 첫 예비 실행의 Pod 1 변경은 파싱 실패 전에 수행되어 해당 실행에서는 자동 복원하지 못했습니다. 후속 최종 실행의 변경은 복원됐으며 이 테스트는 원래부터 격리된 Mock DB 전용입니다. 예비 기록은 Git 제외 경로의 `edge-smoke.json`, `edge-smoke-fixed.json`에 유지합니다.

## 다음에 필요한 사용자 조치

Mac 잠금이 해제되면 실제 Chrome에서 이 과제 화면을 연 뒤 Chrome 작업관리자의 해당 탭 `Memory footprint`를 확인합니다. 다른 탭·확장·GPU 프로세스의 합계나 macOS 활동 모니터의 전체 Chrome 메모리로 대체하지 않습니다. 초기 화면, 500행 창·8개 펼친 부모·상세, 반복 탐색 후 값을 각각 기록하고 표시 단위를 함께 확인해야 합니다.

이번 작업은 추가 검증 도구와 문서 변경이므로 백엔드 전체 테스트는 다시 실행하지 않았습니다. 프론트 단위 테스트 56개·타입 검사·빌드·실제 DB E2E 7개가 재통과했습니다. 최신 상태는 [프로젝트 기준 문서](PROJECT_GUIDE.md)에 반영했습니다. 공백 오류와 문서 링크도 확인했습니다.
