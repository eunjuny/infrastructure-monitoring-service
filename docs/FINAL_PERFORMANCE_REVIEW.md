## 측정 방법

첫 화면은 유효한 SSO 세션에서 navigation을 시작해 Cluster 목록이 조작 가능한 시점까지이며, 인증 복귀 문서부터의 앱 준비 시간도 별도로 측정합니다. 비밀번호 입력은 화면 진입 목표에 포함하지 않습니다.

펼침/접기는 클릭, 필터는 선택 변경, 검색은 디바운스 이후 요청, 수동 갱신은 클릭, 자동 갱신은 폴링 요청부터 실제 결과 DOM과 두 animation frame까지 확인합니다. 최초 펼침은 미조회 계층의 네트워크 요청을 포함합니다. 자동 갱신의 5초 탐지 대기와 화면 반영 시간은 구분합니다.

## 계측 진단과 실행 순서

측정 도구는 브라우저 자체 요청 시간·첫 응답 대기·응답 본문·관측 이벤트 전달 지연을 분리해 보관합니다. URL·쿼리·토큰·헤더는 기록하지 않습니다. 응답 대기는 네트워크·프록시·서버를 함께 포함하므로 SQL 실행 시간으로 단정하지 않습니다. 장시간 main task는 User Timing 시작 시각과 대조할 수 있습니다.

재부팅 직후 예비 실행은 첫 로그인 API의 첫 응답 대기가493.81ms였고 브라우저 보고 지연은0.44ms였습니다. 이 첫 로그인 준비 비용은 서버 응답 경계에 있으며 로그인 후 SSO 진입/탐색 결과와 분리했습니다. 이후3회 예비·20회 최종 실행의 모든 응답 목표를 충족했습니다. 예전 단발 지연의 단일 원인을 확정한 것은 아닙니다.
