# 화면·렌더링·캐시 설계

## 목적과 구성

10만 Pod를 한꺼번에 받아 렌더링하지 않고, 서버 조건 조회와 제한된 페이지 캐시로 탐색합니다. 화면 데이터는 `/api/resources` 실제 계약을 사용하며 테스트 표본은 `frontend/tests`에만 존재합니다. 서버가 중단되어도 샘플 데이터로 대체하지 않습니다.

```text
건수 카드: /summary
왼쪽 계층: Cluster 첫 페이지 → 펼친 부모의 /children
가운데 목록: 유형·부모·상태 → /resources?limit=100 → cursor 순차 조회
이름 검색: 250ms 디바운스 → /search?q=... → 리소스 + 전체 조상 경로
행 선택: /{type}/{id} → 오른쪽 속성·경로
위치 보기: 조상별 /children → 필요 시 매칭 리소스 1개 상세 조회 → 트리 스크롤 이동
수동 갱신: 현재 창·펼친 부모·선택 상세 재조회 → 응답 완료 후 교체
```

이 과제의 계층은 탐색용 Cluster → Node → Namespace → Pod 모델입니다. 실제 Kubernetes의 Namespace와 Node 관계를 그대로 표현한 것이 아닙니다.

## API 조건과 사용자 상태

콘솔 UI 개선은 같은 API·캐시 전략 위에 적용했습니다. 유형 메뉴·건수 카드로 이동하면 조회 조건과 이전 상세를 초기화합니다. 상세는 개요·관계 탭·닫기를 제공하고, 현재 조회창 상태 수만 로컬에서 집계합니다. 모바일 계층은 기본 접힘이지만 컴포넌트·캐시를 유지해 재펼침 시 불필요한 요청을 만들지 않습니다. [콘솔 설계](UI_DESIGN.md)를 참고합니다.

- 목록 조회는 한 유형과 선택적 `parentId`, `status`를 사용합니다. 왼쪽 `→` 또는 상세의 하위 목록 버튼은 자식 유형과 부모 ID를 함께 설정합니다.
- 이름 검색은 선택한 유형 전체에서 수행하고 부모 ID를 보내지 않습니다. 검색어가 있을 때만 `모든 유형`을 제공합니다. 검색어가 사라지면 빈 유형을 Pod로 되돌립니다.
- 상태 필터는 서버 조건에 포함합니다. 왼쪽 계층에는 필터를 적용하지 않아 조상이 필터에서 제외되어 경로가 사라지는 일을 막습니다.
- 필터·검색 범위가 바뀌면 페이지·커서·스크롤을 초기화합니다. 입력 변경 즉시 기존 요청을 취소하고 오래된 목록을 지웁니다. 디바운스 이후 새 요청을 보냅니다.
- AbortController와 요청 세대 번호를 함께 사용합니다. 취소가 늦거나 테스트 대체 응답이 취소 신호를 무시해도 이전 응답이 최신 결과를 덮지 않습니다. 상세 선택도 같은 방식입니다.
- API 오류 400·404·503은 한국어 안내로 표시하며 내부 오류 본문·SQL을 화면에 그대로 출력하지 않습니다. 값은 Vue 텍스트 바인딩으로 표시하며 `v-html`을 사용하지 않습니다.
- 요청마다 JSON 본문 처리까지 10초 제한을 적용합니다. 시간 초과 시 재시도 안내를 표시하며 사용자 취소는 오류로 바꾸지 않습니다. 성공·실패·취소 후 타이머와 취소 리스너를 해제합니다.

## 렌더링과 메모리 상한

### 고정 높이 가상 리스트

목록 행은 60px, 트리 행은 44px입니다. `scrollTop / 행 높이`로 첫 인덱스를 계산하고 뷰포트 앞뒤 5개를 더 표시합니다. 전체 높이 공간과 `translateY`로 스크롤 위치를 표현합니다. 스크롤 계산은 requestAnimationFrame에 모으고 ResizeObserver로 실제 높이를 반영합니다. 변경되지 않은 행은 `유형:ID` 키를 유지합니다.

ResizeObserver가 있으면 마운트 직후 `clientHeight`를 강제로 읽지 않고 관측 콜백으로 높이를 받습니다. 관측 전에는 기본 높이를 사용하고 ResizeObserver가 없는 환경에서만 동기 측정으로 대체합니다. 목록의 날짜·시간은 재사용하는 `Intl.DateTimeFormat`으로 표시해 행마다 로케일 포매터를 반복 구성하는 비용을 줄입니다.

초기에 TanStack Virtual을 계획했지만 현재 요구는 고정 높이·단일 방향 스크롤로 좁습니다. 간단한 범위 계산을 직접 구현하고 미사용 의존성을 제거했습니다. 가변 행 높이, 측정 기반 재배치, 복잡한 스크롤 복원이 필요해지면 검증된 라이브러리를 재검토합니다. 이 구현을 범용 가상화 라이브러리와 동일한 기능으로 설명하지 않습니다.

### 목록 캐시

- 응답 최대 100개, 보관 최대 5페이지 = 500개입니다.
- 마지막 근처로 스크롤하거나 `다음 100개`를 누르면 다음 커서를 요청합니다. 진행 중 중복 요청과 마지막 페이지 추가 요청을 막습니다.
- 여섯 번째 페이지를 받으면 가장 오래된 페이지를 제거하고 제거한 행 높이만큼 스크롤 위치를 보정합니다.
- 제거된 앞부분은 다시 위로 무한 스크롤할 수 없습니다. `처음부터`로 커서를 초기화합니다.
- 서버가 keyset 순차 커서만 제공하므로 전체 10만 건의 임의 인덱스 점프·100,000행 길이의 즉시 탐색 스크롤바는 구현하지 않습니다. 실제 화면은 최대 500행 길이의 이동 창입니다. 전역 Pod 목록을 계속 순차 탐색하는 방식이며 제출 전 과제 기대와 이 UX가 맞는지 확인해야 합니다.

### 계층 캐시

- 부모 페이지 최대 24개, 한 페이지 50개입니다. 검색 위치 보기에서 페이지 밖 목표 1개를 고정할 경우 51개까지입니다.
- 동시에 펼친 부모는 최대 8개이며 추가 펼침 시 가장 오래된 펼침 상태를 접습니다. 접힌 캐시는 여유가 있을 때 재사용하며 상한을 넘으면 오래된 접힌 페이지를 제거합니다.
- 하위 항목의 다음 페이지는 형제 목록을 교체합니다. 이전 커서는 최근 10개만 보관하고 더 이전은 `처음`으로 루트에서 다시 탐색합니다.
- 검색 목표가 첫 페이지에 없으면 목표 ID의 상세 API로 확인한 한 개만 조상 옆에 고정합니다. 모든 형제를 내려받지 않습니다. 새로고침 시 해당 항목도 다시 확인합니다.
- 이 제한은 자료 캐시 상한입니다. 브라우저 전체 메모리가 300MB 미만이라는 측정 결과가 아닙니다.

## 수동 갱신

현재 보관 중인 목록의 첫 커서부터 최대 5페이지를 다시 조회해 교체합니다. 중간 요청이 실패하면 기존 창과 선택·상세를 유지하고 오류를 알립니다. 같은 조건의 갱신에서는 목록을 로딩 표시로 비우지 않습니다. 결과 수가 줄면 유효한 범위로 스크롤을 조정합니다.

펼친 계층 페이지와 선택 상세·건수도 별도로 갱신하며 서로의 오류를 숨기지 않습니다. 영역 간 단일 DB 스냅샷은 보장하지 않습니다. 하단 순번은 이동 창의 위치 안내이지 변동 데이터의 확정 순위가 아닙니다.

## 자동 갱신

초기 요청·검색 디바운스·상세 선택·수동 요청 중에는 자동 요청을 겹치지 않습니다. 조회 완료 5초 뒤 현재 창과 펼친 계층·선택 상세만 다시 조회합니다. 건수 API는 초기 및 수동 갱신에만 사용합니다. 실패 시 기존 값을 유지하고 10·20·40·60초로 간격을 늘립니다. 숨김·오프라인·사용자 해제·화면 해제 시 폴링을 중지합니다.

변경 없는 행 객체는 재사용하고 변경된 행만 같은 키로 교체합니다. 네트워크는 현재 페이지를 재조회하는 방식이며 변경분 전용 API·SSE·WebSocket을 구현한 것은 아닙니다. [상세 정책](LIVE_UPDATES.md)을 참고합니다.

## 검증 경계

Vitest와 Vue Test Utils는 jsdom에서 입력·취소·캐시·선택·갱신·DOM 행 수를 확인합니다. 100,000개 숫자 항목 테스트는 범위·DOM 상한만 검증합니다. 별도로 실제 DB·API의 Chromium E2E에서 탐색·검색·상태 필터·500행 캐시·DB 변경 반영·1,200px 스크롤 유지를 확인했습니다. 실제 DB에 연결한 CPU 4x·캐시 OFF 측정과 반복 탐색 메모리 기록은 [성능 결과](PERFORMANCE_RESULTS.md), 측정 경계는 [성능 기준](PERFORMANCE.md)을 참고합니다.
